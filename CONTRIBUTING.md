# Contributing to Moop

Thank you for your interest in contributing to the Moop project! We welcome contributions from anyone who wants to help build an affordable solution to plastic waste pollution.

## How to Add a Folder via GitHub Web Interface

GitHub's web interface makes it easy to add new folders to the repository without needing to use Git locally. Here's how:

### Method 1: Create a Folder with a New File

1. **Navigate to the repository** on GitHub: https://github.com/asnar00/moop
2. **Click "Add file"** in the upper right corner of the file list
3. **Select "Create new file"** from the dropdown
4. **In the filename field**, type your folder name followed by a forward slash (`/`), then the filename
   - Example: `designs/gripper-v1.md` creates a folder called `designs` with a file `gripper-v1.md`
   - You can create nested folders: `hardware/electronics/schematic.txt`
5. **Add content** to the file
6. **Scroll down** and add a commit message describing your changes
7. **Choose** whether to commit directly to main or create a new branch for a pull request
8. **Click "Commit new file"**

### Method 2: Upload Files to a New Folder

1. **Navigate to the repository** on GitHub
2. **Click "Add file"** in the upper right
3. **Select "Upload files"**
4. **Before uploading**, type your folder name in the "Name your file..." field followed by a forward slash
   - Example: `images/` then drag and drop your files
5. **Add files** by dragging and dropping them into the upload area
6. **Add a commit message**
7. **Commit the changes**

### Important Notes

- **GitHub requires files**: You cannot create an empty folder in Git/GitHub. Each folder must contain at least one file.
- **Nested folders**: You can create multiple levels of folders by using multiple slashes: `folder1/folder2/folder3/file.txt`
- **Best practices**: 
  - Use lowercase letters and hyphens for folder names (e.g., `hardware-designs`)
  - Choose descriptive names that clearly indicate the folder's purpose
  - Include a README.md in new folders to describe their contents

## Suggested Folder Structure

As we grow, here are some suggested folders you might create:

- `designs/` - CAD files, schematics, and technical drawings
- `code/` - Software and firmware
- `hardware/` - Hardware specifications and component lists
- `docs/` - Detailed documentation
- `images/` - Photos, diagrams, and visual assets
- `tests/` - Test results and validation data
- `research/` - Research papers, references, and background materials

## Questions?

If you have questions or need help, feel free to:
- Open an issue on GitHub
- Reach out to the project maintainers

We appreciate your contribution to making the world a cleaner place!
